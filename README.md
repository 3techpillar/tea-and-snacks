# Easy Food — Food Court Ordering App

A mobile-first, demo food-court ordering experience built as a full-stack **npm workspaces monorepo**. It features a decoupled architecture with an **Express / MongoDB** backend and a **Vite / React 19** frontend single-page application (SPA).

Customers can browse vendors, add items to a cart, place orders, and upload a UPI payment screenshot. Vendors can pick their stall and manage live orders, verify payments and move tokens through the kitchen workflow in real time.

---

## Architecture & Tech Stack

This project is structured as an npm workspaces monorepo, decoupling the backend from the frontend while sharing types and constants.

### 1. `packages/shared`
Single source of truth for TypeScript interfaces (e.g. `Product`, `Vendor`, `DemoOrder`) and domain constants. Both the frontend and backend import from here to ensure type safety across the network boundary.

### 2. `apps/backend`
- **Framework**: Node.js + Express
- **Database**: MongoDB (via Mongoose)
- **Auth**: JWT in an `httpOnly` cookie + Zod validation
- **Real-time**: Socket.io for pushing live order updates to vendor dashboards
- **Design Pattern**: Standard MVC (Models, Services, Controllers, Routes, Middleware)

### 3. `apps/frontend`
- **Framework**: React 19 + Vite
- **Router**: TanStack Router (client-side file-based routing)
- **Styling**: Tailwind CSS v4 with custom OKLCH design tokens
- **State**: React Query + React Context (cart stored in `localStorage`)
- **API Integration**: fetch-based API client mapping to backend endpoints (proxied in dev mode to avoid CORS)

## Features

### Customer Flow
- **Home** — hero search, live offers, top vendor cards.
- **Search** — type-ahead suggestions with keyword matching.
- **Vendor Menu** — product grid with tags, cart drawer and sticky cart bar.
- **Cart** — review items, adjust quantities, remove products.
- **Checkout** — customer name + phone, UPI QR payment screenshot upload.
- **Order Tracking** — live token status, payment confirmation, vendor notes.

### Vendor Flow
- **Vendor Picker** (`/vendor`) — choose a stall, see live order counts.
- **Dashboard** (`/vendor/$vendorId`) —
  - Live stats (live orders, pending, unverified payments, collected earnings).
  - Filterable queue: Live / Pending / Preparing / Ready / All.
  - View / confirm / reject UPI payment screenshots.
  - Move tokens through the workflow: Pending → Accepted → Preparing → Ready → Completed.
  - Cancel orders and add customer-facing vendor notes.

## Quick Start

The easiest way to run the full stack locally is to open three terminal windows and start the shared compiler, the backend, and the frontend.

### 1. Install Dependencies
```bash
npm install
```

### 2. Configure Environment Variables
You will need a local MongoDB instance running (defaults to `mongodb://127.0.0.1:27017/easyfood`).
```bash
cp .env.example .env
```

### 3. Build Shared Package & Seed Database
```bash
# Compile shared types so the backend and frontend can consume them
npm run build:shared

# Seed the MongoDB database with vendors, products, offers, and demo vendor logins
npm run seed
```

### 4. Run Development Servers
You can run these via npm workspace commands from the root directory:

**Terminal A (Backend):**
```bash
npm run dev:backend
```
*Runs on `http://localhost:3001`.*

**Terminal B (Frontend):**
```bash
npm run dev:frontend
```
*Runs on `http://localhost:5173`.* (API requests are automatically proxied to port 3001).

---

## Build for Production

To build the entire monorepo for production:
```bash
npm run build
```

This will run TypeScript typechecking across all packages and bundle the frontend via Vite.
